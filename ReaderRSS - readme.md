# ReaderRSS — персональный новостной агрегатор с LLM-суммаризацией (описание на back и на front-части)

Сервер собирает англоязычные RSS-ленты, группирует статьи в сюжеты, суммирует их
через LLM на русском языке и отдаёт через REST API. Android-приложение показывает
ленту сюжетов с фильтрами, офлайн-кэшем и админ-разделом для управления сервером
с телефона.

Ключевой принцип: **сервер делает дорогую работу один раз, клиент читает дёшево
и работает офлайн.**

Актуально на: 2026-11-18.

## Архитектура

```
RSS-ленты ──> pipeline.py ──> PostgreSQL ──> api.py (FastAPI) ──> Android-приложение
                  │                                                    │
                  └── OpenRouter (LLM)                           Room-кэш + DataStore
```

| Слой | Технологии |
|---|---|
| Хостинг | VPS, Docker Compose, каталог `/opt/reasderrss` |
| Домен / TLS | `readerrss.duckdns.org` (DuckDNS), HTTPS через Caddy |
| БД | PostgreSQL в контейнере, том `pgdata` |
| API | FastAPI, живая схема на `/docs` |
| Пайплайн | Python, запуск по systemd-таймеру |
| LLM | OpenRouter, модель `qwen/qwen3.8-27b` |
| Клиент | Android, Kotlin, Jetpack Compose |

## Серверная часть

### Таблицы

`articles`, `stories`, `story_articles`, `feeds`, `runs`, `settings`.

### API

Публичные эндпоинты:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/stories` | лента сюжетов; параметры `categories`, `min_sources`, `exclude_sources`, `since_id`, `limit`, `offset` |
| GET | `/api/v1/stories/{id}` | сюжет с полным списком статей-источников |
| GET | `/api/v1/meta` | категории, источники, время последнего прогона |
| GET | `/health` | проверка живости |

Админские (заголовок `Authorization: Bearer <ADMIN_TOKEN>`):

| Метод | Путь | Назначение |
|---|---|---|
| GET / PUT | `/api/v1/admin/settings` | параметры пайплайна |
| GET / POST | `/api/v1/admin/feeds` | список лент / добавление |
| PATCH | `/api/v1/admin/feeds/{id}` | включение/выключение ленты |
| GET | `/api/v1/admin/runs` | журнал запусков со статистикой |
| POST | `/api/v1/admin/runs` | запрос внепланового прогона (флаг `run_requested`) |

### Пайплайн (`app/pipeline.py`)

1. Выборка статей за окно `lookback_hours`.
2. Группировка статей в кандидаты-сюжеты.
3. Проверка «известности» группы: группа пропускается, если **≥ 70 % её статей
   уже входят в какой-либо сохранённый сюжет** (`story_exists`). Это защищает от
   повторной суммаризации при добавлении одной-двух статей.
4. Суммаризация через `app/llm.py` (промпт требует строго русский язык;
   латиница допускается только в именах собственных).
5. Сохранение сюжета и записи в `runs`. При недоступности модели
   (`ModelUnavailableError`) прогон завершается со статусом `failed`.

Запуск: `news-worker.timer` → `news-worker.service`. Сервис выполняет прогон,
если истёк `pipeline_interval_hours` или установлен флаг `run_requested`.

### Конфигурация

Файл `.env` (секреты и инфраструктура):

```
DATABASE_URL=...
OPENROUTER_API_KEY=...
LLM_MODEL=qwen/qwen3.8-27b
ADMIN_TOKEN=...
```

Параметры пайплайна хранятся **в таблице `settings`** (источник правды);
дефолты заданы в `DEFAULT_SETTINGS` в `pipeline.py`. Ключ появляется в таблице
только после первой записи через PUT или SQL. Переменные `.env` на эти параметры
не влияют и не перезаписывают их при рестарте контейнеров.

Текущие значения:

| Ключ | Значение | Примечание |
|---|---|---|
| `pipeline_interval_hours` | 6 | было 2 |
| `lookback_hours` | 36 | было 48 |
| `min_sources` | 3 | было 2 (дефолт), задано из админки |

### Стоимость LLM

До оптимизации — около $1.2/день (12 прогонов в сутки, неработающая
дедупликация). После увеличения интервала, сужения окна и переписанной
`story_exists` ожидаемый расход $0.1–0.3/день. Контроль — страница Activity
в OpenRouter и поле `skipped_known` в журнале запусков.

Ограничение региона оплаты: модели OpenAI, Anthropic и Google недоступны,
остальные работают. В кабинете OpenRouter автопополнение выключено, на ключе
установлен лимит.

## Android-приложение

### Среда

- Android Studio, проект `newsreader`, пакет `com.example.newsreader`
- minSdk 26, targetSdk/compileSdk — актуальные
- Kotlin 2.x, AGP 8.13, **Gradle 9.5** (9.6 несовместим с AGP 8.x)
- `gradle.properties`: `android.useAndroidX=true`, `org.gradle.jvmargs=-Xmx4096m`

### Стек

Jetpack Compose + Material 3, Hilt, Retrofit + kotlinx.serialization, Room,
DataStore, WorkManager, Navigation Compose, Chrome Custom Tabs.

### Сборки (product flavors)

| Flavor | applicationId | Особенности |
|---|---|---|
| `public` | `com.example.newsreader` | для публикации; код админ-входа не активен |
| `admin` | `com.example.newsreader.admin` | `BuildConfig.ADMIN_FEATURES = true`, вход в админ-раздел |

Обе сборки устанавливаются на одно устройство параллельно. Для разработки —
вариант `adminDebug`.

### Структура кода

```
com.example.newsreader
├── NewsApplication.kt      Hilt, HiltWorkerFactory, перепланирование фонового синка
├── MainActivity.kt         NavHost: feed → story/{id}, settings, admin
├── data/remote | remote    NewsApi, AdminApi, dto/   (пакеты исторически разъехались)
├── local                   StoryEntity, StoryDao, Converters, NewsDatabase
├── repository              NewsRepository: Room + инкрементальный sync по since_id
├── settings                SettingsRepository (DataStore): фильтры, интервал, admin-token
├── sync                    SyncWorker, SyncScheduler (периодика, constraint CONNECTED)
├── di                      NetworkModule (таймауты 10/20/30 с), DatabaseModule
├── util                    userMessage, timeAgo / millisAgo / clockTime, categoryTitle
└── ui/feed, ui/story, ui/settings, ui/admin
```

### Экраны

| Экран | Поведение |
|---|---|
| Лента | чипы категорий из реальных данных; карточки (категория, число источников, заголовок, 3 строки summary, источники, давность); сортировка «день ↓, источники ↓, id ↓»; прокрутка наверх при смене чипа; нижняя панель «обновлено N мин · ЧЧ:ММ», кнопки обновления и настроек; автосинк при старте; при ошибке сети — снэкбар, лента из кэша остаётся |
| Сюжет | заголовок, полный текст, ключевые факты, источники, сгруппированные по сайту (одна карточка = один сайт), открытие оригинала в Custom Tab, кнопка «Повторить» при ошибке |
| Настройки | категории (чекбоксы), минимум источников (1–10), источники (переключатели), стоп-слова (регистронезависимо по заголовку и тексту), интервал фонового обновления (2/4/6/12/24 ч); в admin-flavor — вход в админ-раздел |
| Админ | вход по `ADMIN_TOKEN`, параметры пайплайна, ленты (вкл/выкл, добавление), журнал запусков со статистикой, «Запустить сейчас», выход |

### Проектные решения

- Хранятся **скрытые** категории и источники, а не выбранные: всё новое на
  сервере видно пользователю по умолчанию.
- Фильтры применяются в памяти к потоку из Room (`combine` в `FeedViewModel`),
  а не в SQL — проще комбинировать условия, при сотнях сюжетов это мгновенно.
- Скрытый источник убирает сюжет только если он был у сюжета единственным.
- Сетевые ошибки переводятся в человеческие сообщения (`util/userMessage`);
  технический стектрейс уходит только в Logcat.
- Детали сюжета (список статей) не кэшируются — экран сюжета требует сеть.

## Быстрый старт

### Сервер

```bash
cd /opt/reasderrss
cp .env.example .env            # заполнить DATABASE_URL, OPENROUTER_API_KEY, LLM_MODEL, ADMIN_TOKEN
docker compose up -d --build
docker compose run --rm worker  # ручной прогон пайплайна
systemctl enable --now news-worker.timer
```

Проверка: `https://readerrss.duckdns.org/health`, `https://readerrss.duckdns.org/docs`.

### Приложение

1. Открыть проект в Android Studio, дождаться Gradle sync.
2. Build Variants → `adminDebug`.
3. Подставить адрес сервера в `BASE_URL` (`di/NetworkModule.kt`).
4. Запустить на устройстве; в настройках → «Администрирование сервера» → ввести `ADMIN_TOKEN`.

## Эксплуатация и диагностика

Параметры пайплайна в БД:

```bash
docker compose exec postgres psql -U news -d news -c "SELECT key, value, updated_at FROM settings;"
```

Последние прогоны:

```bash
docker compose exec postgres psql -U news -d news -c "SELECT id, started_at, finished_at, status FROM runs ORDER BY id DESC LIMIT 5;"
```

Таймер и логи воркера:

```bash
systemctl status news-worker.timer
journalctl -u news-worker.service -n 50
```

Изменение параметров без редеплоя (с сервера, bash):

```bash
curl -X PUT -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"pipeline_interval_hours": 6, "lookback_hours": 36}' \
  https://readerrss.duckdns.org/api/v1/admin/settings
```

Примечание для Windows: в cmd/PowerShell одинарные кавычки не работают — используйте
`curl.exe` с экранированными двойными кавычками, Swagger UI на `/docs` или админ-раздел
приложения.

Признак проблемы: `run_requested = true` в таблице `settings` дольше одного интервала
означает, что воркер не запускался — проверить таймер. Кэш приложения маскирует такой
отказ: лента выглядит живой.

## Открытые вопросы и технический долг

### Требуют проверки

- [ ] `run_requested = true` в таблице — убедиться, что `news-worker.timer` жив и прогоны идут.
- [x] Сохранение `min_sources` из админки — исправлено (newsreader `8dc6e68`, `@JvmSuppressWildcards` в `AdminApi.putSettings`), проверено на устройстве 2026-11-19.
- [ ] Фактическое срабатывание `SyncWorker` в фоне не подтверждено (учесть усыпление фоновых приложений на Samsung).
- [ ] Фикс клавиатуры в настройках (`imePadding()` на Scaffold, `adjustResize` в манифесте) — проверить.

### Технический долг

- Пакеты `data.remote` и `remote` привести к единому виду (Refactor → Move).
- `applicationId` `com.example.*` не примет Google Play — сменить перед публикацией (только в Gradle, код не трогать).
- Admin-токен хранится в обычном DataStore; для admin-сборки можно перейти на EncryptedSharedPreferences.
- `lastSyncAt` живёт в памяти — после перезапуска «ещё не обновлялось» до первого синка.
- Base URL зашит константой, а не вынесен в настройки.
- Словарь категорий захардкожен в `util/Categories.kt`; новые категории отобразятся слагом.
- Удаление RSS-лент не реализовано (осознанно — есть вкл/выкл); эскиз `DELETE /admin/feeds/{id}` готов.
- Нет индикатора устаревания данных в ленте (по `last_run_at` из `/meta`).

## Ретроспектива

### Что сработало

- Разделение «сервер думает, клиент читает»: клиент почти не генерирует трафика
  (инкремент по `since_id`), стартует мгновенно, работает офлайн.
- Параметры пайплайна в БД + админ-API: обе «ручки экономии» крутились без редеплоя —
  сначала curl'ом, затем с телефона.
- Реактивная цепочка Room/DataStore → `combine` → UI: фильтры, синк и настройки
  сходятся в одном `uiState`, целый класс багов рассинхронизации не возник.
- Flavors вместо «скрытого раздела по паролю»: публичная сборка физически не содержит
  админского входа.

### Чему научились

- Большинство ошибок сборки были про **размещение файлов**, а не про код: файлы в
  `build/generated`, пакет в корне `java`, функция за пределами `object`, заготовка
  `annotation class` над вставленным интерфейсом. Правило: создавать файлы только
  кликом по целевому пакету, тип **File**, сверять строку `package` с путём.
- Версии инструментов в студии всегда новее любых внешних инструкций — при конфликте
  побеждают версии студии (подтвердилось на AGP, Gradle, пакете конвертера Retrofit).
- Экономия на LLM должна подтверждаться метрикой (`skipped_known`, Activity в кабинете),
  а не расчётом: реальный расход оказался в разы выше прогноза из-за неработающей
  дедупликации.
- Кэш маскирует серверные отказы — нужен явный сигнал устаревания данных в интерфейсе.
- Windows-терминал ломает кавычки в JSON — админские операции удобнее делать через
  Swagger UI, по SSH или из приложения.

**Итог:** продуктовое ядро готово от RSS до экрана телефона. Оставшееся — верификация
и полировка, а не недостроенные части.

## Дорожная карта

1. Закрыть пункты из раздела «Требуют проверки» (в первую очередь — таймер).
2. Индикатор устаревания данных в ленте.
3. Подготовка к публикации: уникальный `applicationId`, иконка, release-подпись,
   перенос base URL в настройки.
4. Уведомления о новых сюжетах: FCM + рассылка после прогона при наличии
   Firebase-аккаунта; иначе локальные уведомления из `SyncWorker` (работают без
   Google-сервисов и закрывают большую часть потребности).
